## Round 2 corrections (supersede the rows above where they conflict)

| # | Correction | From |
|---|---|---|
| R1 | **Capped API-error counter.** New per-article `api_errors` counter (per step). API/transport errors and "bad JSON" revert status without counting a content attempt, but each adds 1 to `api_errors`; at **5** the article is skipped with the reason. `refusal` = content verdict (counts an attempt). `max_tokens` = one retry with double max_tokens, then a counted failure. No request can be re-sent and re-paid forever. Alcohol fallback stays: after 3 API errors → treated as alcohol. | A1, C1 |
| R2 | **Partial batch failures:** always apply the successful results (already paid); revert only the failed articles (subject to R1); report counts in Summary. The ">50% → abandon" rule is dropped. | A5, C-corr |
| R3 | **Image polling exempt from backoff.** `poll_predictions` is its own step, runs every tick (also while paused), never skipped by P2 backoff. | A2 |
| R4 | **Recovery per article, not per kind.** Every job row stores its article IDs in its payload (pilot `run_now` also writes a job row with state `sync`). Recovery reverts only pending articles not listed in any open job; `sync` jobs are abandoned at startup; `copy_attempts−1` floored at 0. | A3, C4 |
| R5 | **Batch create window.** Before `create_batch`, save a `creating` job row with the article IDs; after success store the batch ID immediately (logged). On recovery of a `creating` row with no batch ID, look for a matching batch via `batches.list()` (created after the row's timestamp, same request count) before re-sending; if found, adopt it. | A4, C-corr |
| R6 | **Transactions done safely.** One `tx()` context manager: `BEGIN IMMEDIATE` … `COMMIT`, `ROLLBACK` on any exception; the P2 step handler also rolls back if `con.in_transaction`; no network call (API, result paging, reconcile search) ever runs inside a transaction. | C2, B6 |
| R7 | **Pause can't be bypassed.** If reading Settings fails, the tick runs no steps (only image polling and reports). A missing "Pause" row counts as paused. | C3 |
| R8 | **P2 backoff is per step + pool/wave**, never global. | C-C5 |
| R9 | **P5 timeout by prediction age**: any prediction older than 30 min (from its saved `created` time) is cancelled (best effort) and failed, even if `client.get` keeps raising. | C-corr |
| R10 | **Shutdown:** SIGTERM sets a stop event; the 60 s sleep uses `Event.wait(60)` so it wakes immediately. Recovery (R4/R5) is the real safety net, since Railway's grace period may be very short [guess]. | C-corr |
| R11 | **Startup guards:** volume-mount guard skipped when `DRY_RUN=1`. **Single-worker lease** in kv (PID + heartbeat each tick); a second worker waits while another holds a fresh lease (protects against overlapping deploys on one SQLite file). | C-corr |
| R12 | **P9 lost-job rule tightened.** The 10-try rule applies only when the job is missing from search or DONE with unlistable results. A RUNNING job, or PENDING after `run_requested`, only gets the 24 h limit; before rebuilding a PENDING-after-run job, remove it with `mutate_batch_job(operation.remove)`; if Google answers `CAN_ONLY_REMOVE_PENDING_JOB`, keep waiting. | B1 |
| R13 | **Reconcile covers everything:** campaign budgets (`campaign_budget.name`), campaigns, campaign criteria (location/language), campaign labels, ad groups, the 18-24 `ad_group_criterion` AGE_RANGE exclusion, image assets (by name), and ads (ad group + final URL). | B2 |
| R14 | **P11 order:** collision check runs after reconcile, before each job, only for campaigns without `campaign_res`; it also checks budget names (`"<name> | budget"`). | B3 |

Labels: fetch all `label.name`/`label.status`, compare case-insensitively in Python; a match that is REMOVED → reported (`CANNOT_APPLY_INACTIVE_LABEL`), not applied or recreated. | B4 |
